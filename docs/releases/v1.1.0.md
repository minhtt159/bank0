The release that puts the client API on the internet. Everything else here either had to land before that happened, or is the front end catching up.

## Upgrade first, then read the rest

**The client API hostname changed.** It is `bank0-api.hnimn.art` now, not `api.bank0.hnimn.art`, and the chart's `api.host` default changed with it. If your install overrides `api.host` you are unaffected; if it does not, the HTTPRoute this chart renders will claim a different hostname after the upgrade. Cloudflare's Universal SSL covers the apex and exactly one wildcard level, so the two-label name had no edge certificate — flattening it was cheaper than paying for Advanced Certificate Manager, and it also brought the name under the tunnel's existing `*.hnimn.art` ingress rule.

**Two migrations run in the pre-upgrade Job:** `00019_login_returns_must_change_password.sql` and `00020_bcrypt_cost_12.sql`. Both are reversible.

**The `sha-<shortsha>` image tag no longer exists.** Merging to main publishes nothing now. If you were deploying with `--set image.tag=sha-...`, tag the commit instead.

## What changed

**The client API is reachable from the internet, and only by our Workers.** The production `bank0-api` HTTPRoute moved to the platform's external Gateway behind a `cloudflared` tunnel, with OWASP CRS and a Valkey-backed per-IP limit on `/auth/*` in front of it. The hostname is then gated by a Cloudflare Access policy in Service Auth mode, so the only callers that get through are the Workers holding the service token — a browser aimed straight at it is refused at the edge. The operator portal did not move and will not: it is the admin surface and still has no MFA ([#116](https://github.com/minhtt159/bank0/issues/116)).

This is what the same-origin `/api/*` design was for. Because the SPA never names the API host, the API host can be made unreachable to browsers — which is not an option once a client has to call it directly.

**`must_change_password` now binds the client API too.** `00018` only taught the portal to check it: `requireSession` enforced the flag, `requireJWT` did not. So an admin who flagged a customer's account — the "evidence of compromise" action — watched that customer sign back in with the old password and use the entire client API. The two functions that authenticate now report the flag alongside the credentials, the API mints it into the access token, and the client surface gates on it without a second round trip. ([#99](https://github.com/minhtt159/bank0/issues/99))

**bcrypt moves from cost 10 to 12.** Ten is exactly OWASP's floor, which is a strange place to sit once the login endpoint is public. Every function that writes a hash now writes at 12, and every function that verifies one re-hashes at 12 on success — so existing hashes upgrade as people sign in rather than in a migration that has no plaintext to work with. A dormant account keeps its cost-10 hash until someone uses it. Nothing re-costs on a *failed* login, deliberately: that would let an unauthenticated caller spend 4× the CPU per guess. Account PINs stay at cost 10, because a four-digit PIN is bounded by its 10⁴ search space, not by the KDF. ([#121](https://github.com/minhtt159/bank0/issues/121))

**The console CSP gained `script-src 'self'`.** htmx is vendored and served from `/static`, and the console carries no inline `<script>` and no inline event attributes — `theme-boot.js` and `console.js` own what used to be `onclick=` and `hx-on:click`. Both failure modes are silent in a browser, so `TestHTMXSelfHosted` and `TestConsoleHasNoInlineScript` fail the build instead of leaving you to notice. No `default-src`: this locks down script, the injection vector that matters, without enumerating every image and font source. ([#122](https://github.com/minhtt159/bank0/issues/122))

**htmx 2 → 4 on the console, at behavioural parity.** Plus server-rendered toasts, deep-linkable panels, a scroll-safe layout with an icon rail, request spinners, and focus/aria work.

**Catppuccin on both front ends**, with a five-flavour picker, following the OS preference by default.

**Go 1.27.**

**Releases are the only thing that publish or deploy.** A merge to main runs the gates and stops there; a `v*` tag publishes the image, the chart, the GitHub release, and — on final tags only — deploys the customer PWA to Cloudflare. That last one is the first CI-driven deploy this repo has ever had, and it exists because the Worker lives somewhere CI can actually reach. The cluster still does not: `helm upgrade` remains an operator command, promoted through Argo CD and Kargo.

## Known skew, by design

The PWA now deploys at tag time, while production is promoted by Kargo plus a human, hours or days later. So the front end for a release serves against the previous release's API for that window. That is tolerable only because the Worker is a static host and a proxy with no business logic — keep API changes additive and put new UI behind a capability check. It stops being tolerable the day the Worker becomes a token-holding BFF, which is also when it earns a staging Worker of its own (`docs/07` §6).

## Still open

The WAF runs in `DetectionOnly` for the API hostname until its match log has been read against real logins, transfers and disputes — this API posts exactly what CRS scores. The real client IP behind the Worker subrequest has not been measured yet, so `trustedProxyHops` is set from reasoning rather than evidence. And the breached-password check ([#120](https://github.com/minhtt159/bank0/issues/120)) is worth more now that the login endpoint is public than it was when it was filed.
