A patch release. No migrations, no schema change, no API change: the operator
portal gets the hostname and the login limiter it needs before it can be exposed,
and `/docs` renders again.

## Upgrade first, then read the rest

**The portal hostname changed.** It is `bank0-portal.hnimn.art` now, not
`portal.bank0.hnimn.art`, and the chart's `portal.host` default changed with it.
If your install overrides `portal.host` you are unaffected; if it does not, the
HTTPRoute this chart renders will claim a different hostname after the upgrade.
Same reason the API host was flattened in v1.1.0: Cloudflare's Universal SSL
covers the apex and exactly one wildcard level, so a two-label name has no edge
certificate. Staging keeps its nested names — it never meets the Cloudflare edge.

**Nothing else moves.** No migrations, so the pre-upgrade Job is a no-op; the
drop-in from 1.1.0 is the hostname and nothing more.

## What changed

**`/docs` rendered a blank page on every deployment.** `securityHeaders` sets
`script-src 'self'` on every surface (v1.1.0, #122), and the Scalar UI's only
script comes from `cdn.jsdelivr.net` — so the browser refused the one thing that
draws the page. The status was 200 and the HTML was valid; only a browser knew.
That route now allows that one origin and nothing else. The script is SRI-pinned,
so the exception costs availability (jsdelivr reachable), not integrity.
`TestDocsCSPAllowsItsOwnScripts` asserts the invariant rather than the hostname:
every script source a page references must be permitted by the CSP that same
response carries, and any off-origin one must carry an integrity digest.

**The console login is rate-limited per IP.** `POST /login` had only the
per-account DB lockout; the client's `/auth/login` has had the per-IP sliding
window since it went public. The console is now wired through the same
middleware — one line, the limiter and its 429 test already existed.

**The portal's exposure is documented, and the chart stops promising it will
never happen.** `docs/04` §3 gains the console's own checklist: Cloudflare Access
plus Entra at the edge, the Access JWT re-verified by an Envoy `SecurityPolicy`,
`/login` rate-limited at the gateway, `/health` `/readyz` `/metrics` answered 404,
`/docs` kept, the LAN route kept as break-glass, credentials rotated before the
route exists. The portal still has no MFA of its own (#116); an identity-aware
gate with MFA in front of it is what stands in on this install, and the values
comment says that instead of "nothing about it needs to leave the LAN".

**The Worker states that the custom domain is its only front door.**
`preview_urls` was the product of two defaults and a dashboard toggle, and a
preview URL is a publicly reachable `*.workers.dev` copy of the same Worker
carrying the same Access service token — it would proxy `/api/*` straight into
the gated API with nothing in front of it. `wrangler.toml` decides it now.

## Still open

Everything the v1.1.0 notes left open is still open: the WAF is in
`DetectionOnly` for the API hostname, `trustedProxyHops` is set from reasoning
rather than a measurement, and the breached-password check (#120) is unbuilt.
The portal route itself is not live — this release is what makes it safe to
create.
